# 처음 시작하는 사람을 위한 안내서

개발을 해 본 적이 없어도 이 문서를 위에서부터 차례대로 따라 하면 됩니다.
모르는 단어가 나오면 맨 아래 [용어 사전](#9-용어-사전)을 보세요.

> 이 문서의 명령어 결과는 2026-11-24, macOS 27 · Node 23.5 · MacBook Air(M1, 8GB)에서 실제로 실행해 확인했습니다.
> 단, 설치 단계(2장)는 이미 도구가 설치된 Mac에서 작성했기 때문에, 처음부터 따라 해 보며 확인하지는 못했습니다. 막히는 곳이 있으면 알려 주세요.

---

## 1. 이 시스템은 무엇을 해 주나요?

웹사이트·웹앱을 **AI에게 만들게 하고, 제대로 만들었는지 자동으로 검사한 뒤, 마지막으로 내가 눈으로 확인하는** 작업 틀입니다.

```
 ① 내가 원하는 기능을 글로 적는다 → AI가 명세로 정리, 내가 승인
        ↓
 ② AI 에이전트가 코드를 고친다
        ↓
 ③ 검사 스크립트(verify.sh)가 자동으로
    - 코드 검사 (스타일, 타입, 서식)
    - 빌드 (실제 배포할 형태로 만들기)
    - 로직 테스트
    - 보이지 않는 브라우저로 사이트를 열어 버튼을 눌러 보고 스크린샷 저장 (컴퓨터 화면·마우스는 건드리지 않음)
        ↓
 ④ 결과 보고서(verification.md)와 스크린샷(PC 화면, 휴대폰 화면)이 만들어진다
        ↓
 ⑤ 내가 보고서와 스크린샷을 보고 승인한다 → 원하면 Vercel에 배포
```

핵심은 **AI가 "다 됐어요"라고 말하는 것을 그대로 믿지 않는다**는 점입니다. 검사 스크립트가 실제로 실행한 결과와 스크린샷이 증거가 됩니다.

지금 들어 있는 사이트는 연습용 예제(WebStarter)입니다. "0번 눌렀습니다"라는 글자와 `증가`, `초기화` 버튼이 있습니다.
아래 "서버 예제: 메모" 링크를 누르면 메모를 저장하고 지우는 화면이 나옵니다. 메모는 컴퓨터 안의 작은 DB(`.data/` 폴더)에 저장되므로 새로고침해도 남습니다. 서버가 필요 없는 사이트를 만들 때는 이 예제가 빠집니다.

## 2. 준비하기 (처음 한 번만)

### 2-1. 터미널 열기

`Command(⌘) + Space` → "터미널" 입력 → Enter. 이 문서의 명령어는 모두 터미널에 붙여 넣고 Enter를 누르면 됩니다.

### 2-2. Homebrew와 Node.js 설치

Homebrew(맥용 프로그램 설치 도구)가 없다면 [brew.sh](https://brew.sh)의 설치 명령을 실행하고, 끝에 나오는 "Next steps" 명령도 실행합니다. 그다음:

```bash
brew install node@24
node -v     # v24... 처럼 버전이 나오면 성공
```

### 2-3. 프로젝트 폴더 놓을 위치

이 프로젝트 폴더는 **홈 폴더 바로 아래**(예: `/Users/내이름/wnas`)에 두는 것을 권장합니다.
iCloud로 동기화되는 `데스크탑`이나 `문서` 폴더에 두면 `node_modules`의 수많은 파일이 계속 동기화되어 느려집니다.

## 3. 처음 실행해 보기

### 3-1. 프로젝트 폴더로 이동하고 필요한 것 설치

```bash
cd ~/wnas
npm ci                             # 필요한 부품 설치 (1분 정도)
npx playwright install chromium    # 검사용 브라우저 설치 (컴퓨터에 한 번만)
```

### 3-2. 전체 검사 실행

```bash
./scripts/verify.sh all
```

1분 정도 걸립니다. 그동안 컴퓨터를 평소처럼 써도 됩니다(브라우저가 화면에 나타나지 않습니다).
끝나면 마지막에 보고서가 나오고 맨 위에 `전체 결과: **PASS**`가 보이면 성공입니다.

### 3-3. 사이트를 직접 열어 보기 (선택)

```bash
npm run dev
```

브라우저에서 http://localhost:3000 을 엽니다. 코드를 고치면 바로 반영됩니다. 끝낼 때는 터미널에서 `Control + C`.

## 4. 결과 확인하기

### 4-1. 결과 폴더 열기

```bash
open "$(cat .artifacts/latest-run)"
```

### 4-2. 결과 폴더 안에 있는 것

| 이름                                                | 내용                                                           |
| --------------------------------------------------- | -------------------------------------------------------------- |
| `verification.md`                                   | 검사 보고서 (가장 먼저 봄)                                     |
| `screenshots/desktop/...`, `screenshots/mobile/...` | PC 화면, 휴대폰 화면 스크린샷                                  |
| `failures/`                                         | 실패한 테스트가 있을 때만: 실패 순간의 화면, 영상, 기록(trace) |
| `e2e/playwright-report/`                            | 브라우저 테스트의 자세한 보고서                                |
| `*.log`                                             | 단계별 기록. 실패 원인을 찾을 때 봄                            |

### 4-3. `verification.md` 읽는 법

- `전체 결과`: PASS면 모든 검사 통과. FAIL이면 어느 줄이 FAIL인지 봅니다.
- `NOT RUN`: 그 검사는 실행하지 않았다는 뜻입니다(통과가 아님).
- `화면 검토: PENDING`: 스크린샷을 사람이 아직 보지 않았다는 뜻입니다. 직접 열어 확인하세요.

### 4-4. 스크린샷 확인

- 글자가 잘리거나 겹치지 않는지, 휴대폰 화면에서도 버튼이 잘 보이는지 봅니다.
- 스크린샷은 테스트가 "숫자가 2가 됐다" 같은 확인을 통과한 **뒤에** 찍은 것입니다.

자세한 테스트 보고서를 브라우저로 보려면:

```bash
npx playwright show-report "$(cat .artifacts/latest-run)/e2e/playwright-report"
```

## 5. AI에게 첫 기능 시켜 보기

이 폴더에서 Claude Code(`claude`)를 실행합니다. 에이전트는 `AGENTS.md`의 규칙(검사 실행, 거짓 보고 금지, 커밋·배포 금지 등)을 따릅니다.
AI는 바로 코드를 고치지 않고 **명세 → 사람 승인 → 구현** 순서로 일합니다.

### 연습 예제: 숫자를 1 내리는 버튼 추가

**1단계 — 요구사항 말하기.**

> /spec 초기화 버튼 왼쪽에 숫자를 1 내리는 감소 버튼을 추가해 줘. 숫자는 0보다 작아지지 않아야 해.

AI가 `docs/PRODUCT_SPEC.md`를 만들고(코드는 아직 건드리지 않음) 기능 번호(예: `F-1`), 수용 기준, 미결 질문을 알려 줍니다.

**2단계 — 명세 읽고 승인하기.** `docs/PRODUCT_SPEC.md`를 열어

- 수용 기준이 원하는 동작과 같은지 확인하고, 다르면 고치거나 AI에게 말합니다.
- "미결 질문"에 답합니다. 다 정리되면 `- 없음`이 됩니다.
- 마음에 들면 맨 위 `- 상태: 초안`을 `- 상태: 승인`으로 직접 바꿉니다.

**3단계 — 구현 시키기.**

> /implement F-1

AI는 명세가 승인됐는지 먼저 검사하고, 승인됐다면 구현 → `verify.sh all` → 명세의 "검증 결과"에 기록합니다.

### 에이전트가 끝났다고 하면 확인할 것

1. 결과 폴더의 `verification.md`가 `전체 결과: **PASS**`인지
2. 단위 테스트, E2E 테스트 개수가 **늘었는지**
3. 새 스크린샷(PC·휴대폰)에 감소 버튼이 보이고 숫자가 기대대로 바뀌었는지
4. 명세의 "검증 결과"에서 수용 기준마다 PASS인지. 확인했으면 `- [ ]`를 `- [x]`로 직접 체크

## 6. 자주 쓰는 명령어

모두 프로젝트 폴더에서 실행합니다. (`cd ~/wnas` 먼저)

| 명령어                                         | 하는 일                                                           | 걸리는 시간 |
| ---------------------------------------------- | ----------------------------------------------------------------- | ----------- |
| `./scripts/verify.sh all`                      | 전체 검사 (보통 이것만 쓰면 됨)                                   | 약 1분      |
| `./scripts/verify.sh unit`                     | 로직 테스트만                                                     | 수 초       |
| `./scripts/verify.sh e2e`                      | 빌드 + 브라우저 테스트만                                          | 30초~1분    |
| `npm run dev`                                  | 개발용 사이트 열기 (http://localhost:3000)                        | 즉시        |
| `npm run format`                               | 코드 서식 자동 정리 (Prettier 검사가 FAIL일 때)                   | 수 초       |
| `./scripts/check-spec.sh docs/PRODUCT_SPEC.md` | 명세가 승인됐는지, 빠진 칸이 없는지 검사                          | 즉시        |
| `./scripts/prune-evidence.sh`                  | 쌓인 결과 폴더 목록과 크기 (삭제하지 않음)                        | 즉시        |
| `./scripts/deploy.sh`                          | Vercel에 미리보기 배포 ([README 7절](../README.md#7-배포-vercel)) | 1~3분       |

검사는 **한 번에 하나만** 실행하세요. 동시에 실행하면 스크립트가 두 번째 실행을 막습니다.

## 7. 문제가 생겼을 때

| 화면에 나온 메시지                                    | 원인                                              | 해결                                                                    |
| ----------------------------------------------------- | ------------------------------------------------- | ----------------------------------------------------------------------- |
| `command not found: node` 또는 `npm`                  | Node.js 미설치                                    | 2-2 실행                                                                |
| `브라우저 없음: npx playwright install chromium`      | 검사용 브라우저 미설치                            | `npx playwright install chromium`                                       |
| `permission denied: ./scripts/verify.sh`              | 실행 권한이 사라짐                                | `chmod +x scripts/*.sh`                                                 |
| `다른 verify.sh가 실행 중입니다`                      | 다른 검사가 실행 중이거나 이전 검사가 강제 종료됨 | 실행 중인 검사가 정말 없으면 `rmdir .artifacts/verify.lock`             |
| `린트: ... Prettier FAIL`                             | 코드 서식이 규칙과 다름                           | `npm run format` 후 다시 검사                                           |
| `린트: ESLint FAIL` 또는 `타입 검사 FAIL`             | 코드 규칙 위반 또는 타입 오류                     | `eslint.log`, `tsc.log`를 에이전트에게 보여 주고 "고쳐 줘"              |
| `빌드: FAIL`                                          | 코드에 오류가 있음                                | `build.log`를 에이전트에게 전달                                         |
| `E2E 테스트: FAIL`                                    | 화면 동작이 기대와 다름                           | `failures/` 폴더의 실패 화면을 보고, `e2e.log`와 함께 에이전트에게 전달 |
| `Cannot read properties of null (reading 'edgesOut')` | 패키지 추가 시 npm 10.9 버그                      | Node 24로 올리거나 `npx npm@11 install -E <패키지>`                     |

## 9. 용어 사전

| 용어                        | 뜻                                                                                             |
| --------------------------- | ---------------------------------------------------------------------------------------------- |
| 터미널                      | 글자로 Mac에 명령을 내리는 프로그램                                                            |
| Node.js / npm               | 웹 개발 도구를 실행하는 프로그램 / 부품(패키지)을 설치하는 도구                                |
| `node_modules`              | 설치된 부품 폴더. 지워도 `npm ci`로 다시 만들 수 있음                                          |
| Next.js / React             | 웹앱을 만드는 틀 / 화면을 만드는 방법                                                          |
| TypeScript                  | 값의 종류(숫자, 글자)를 미리 적어 실수를 막는 JavaScript                                       |
| 빌드                        | 코드를 실제 배포할 형태로 만드는 과정                                                          |
| 단위 테스트 (Vitest)        | 계산 같은 로직만 따로 확인하는 테스트                                                          |
| E2E 테스트 (Playwright)     | 실제 브라우저로 사이트를 열어 클릭하며 확인하는 테스트                                         |
| headless                    | 브라우저를 화면에 띄우지 않고 실행하는 것. 그래서 검사 중에도 컴퓨터를 쓸 수 있음              |
| 명세 / 수용 기준            | 무엇을 만들고 어떻게 확인할지 적은 문서 / "이렇게 되면 완성"이라는 조건 (`F-1.AC-1`)           |
| assertion                   | 테스트 안의 "이 값은 반드시 이래야 한다"는 확인 문장                                           |
| Lint (ESLint) / Prettier    | 코드 규칙 검사 도구 / 코드 서식 정리 도구                                                      |
| 접근성 검사 (axe)           | 화면 낭독기 사용자 등도 쓸 수 있는지(대비, 버튼 이름 등) 자동 검사                             |
| Vercel                      | 웹앱을 인터넷에 올려 주는 서비스. 미리보기 주소와 실제 주소(프로덕션)가 있음                   |
| 환경 변수 / `.env.local`    | 비밀번호·키 같은 설정 값 / 그 값을 두는 파일 (Git에 올라가지 않음)                             |
| 커밋 / Git                  | 변경 내용을 기록으로 남기는 것 / 그 기록을 관리하는 도구                                       |
| 종료 코드                   | 명령이 끝날 때 남기는 숫자. 0은 성공, 그 외는 실패                                             |
| 서버 / API                  | 화면 뒤에서 데이터를 저장·처리하는 부분 / 다른 프로그램이 주소(예: `/api/memos`)로 부르는 기능 |
| DB (Postgres, PGlite, Neon) | 데이터를 저장하는 곳 / 그 종류 / 내 컴퓨터 안에서 도는 Postgres / 인터넷의 Postgres 서비스     |
| 마이그레이션                | DB 표의 모양을 바꾸는 기록(SQL 파일, `drizzle/`). 순서대로 적용됨                              |
| Server Action               | 화면의 버튼·폼이 서버에서 바로 실행하는 함수                                                   |
