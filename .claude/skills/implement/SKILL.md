# 승인된 기능 구현

대상 기능: $ARGUMENTS

## 1. 관문 (하나라도 실패하면 구현하지 않고 이유를 보고한 뒤 멈춘다)

```bash
./scripts/check-spec.sh docs/PRODUCT_SPEC.md
```

- 종료 코드가 0이 아니면 멈춘다 (초안 상태, 미결 질문 남음, 형식 오류 등). 명세를 대신 승인하지 않는다.
- 대상 기능이 명세에 없으면 멈춘다. 기능 번호가 없으면 `기능 상태: 대기`인 첫 기능을 제안만 하고 멈춘다.
- 대상 기능이 이미 `구현 완료`이면 다시 구현할지 묻는다.

## 2. 구현

- `AGENTS.md`의 아키텍처·완료 정의·테스트 작성 규칙을 따른다. Next.js API를 쓰기 전에 `node_modules/next/dist/docs/`의 해당 문서를 읽는다(학습한 내용과 버전이 다를 수 있다).
- 명세의 수용 기준(`F-n.AC-n`)마다 테스트를 만든다. 테스트 이름에 해당 수용 기준 번호를 적는다(예: `test("F-1.AC-2: ...")`).
- 로직은 `lib/`에 두고 Vitest로, 화면 흐름은 `e2e/`의 Playwright 테스트로 검증한다. 스크린샷은 assertion 뒤에 `capture(page, testInfo, "NN-상태-설명")`로 남기고, 이름은 테스트 계획 표에 적힌 이름을 그대로 쓴다.
- 명세에 없는 기능, 외부 서비스, npm 패키지, 환경 변수는 추가하지 않는다. 필요해 보이면 멈추고 `/spec`으로 명세 변경을 제안한다.
- 명세 자체(수용 기준, 범위)를 바꾸지 않는다.

## 3. 검증

- `./scripts/verify.sh all` 실행 → 실행 폴더의 `verification.md` 확인. 브라우저는 headless라 사용자의 화면을 건드리지 않는다.
- 스크린샷(데스크톱·모바일)을 직접 열어 확인한다.

## 4. 명세에 기록 (이 단계에서 명세에 쓰는 것은 이 두 가지뿐)

- `## 검증 결과`에 추가 ("- 아직 없음"은 지운다):
  ```
  ### F-n (날짜)
  - 실행 폴더: .artifacts/runs/<시각>
  - 전체 결과: PASS|FAIL
  - F-n.AC-1: PASS|FAIL|NOT RUN — 근거(테스트 이름, 스크린샷)
  - 화면 검토: 확인함 / 사람 검토 필요 — 메모
  ```
- 모든 수용 기준이 PASS이고 전체 결과가 PASS일 때만 그 기능의 `기능 상태: 구현 완료`로 바꾼다.
- 수용 기준 체크박스(`- [ ]`)는 사람이 최종 확인하며 체크한다. AI는 체크하지 않는다.

## 5. 보고
